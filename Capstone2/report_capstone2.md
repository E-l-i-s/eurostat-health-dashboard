# Capstone 2 — Austria Energy Transition: Database Design & SQL Queries

## 1. Conceptual ERD Design

The conceptual entity-relationship diagram models the Austria Energy Transition domain at a high level, identifying 8 core entities and their business relationships.

### Entities

| Entity | Description |
|---|---|
| **Country** | Represents Austria as the nation being analyzed. Contains basic identification data. |
| **Year** | Temporal dimension providing the time context for all measurements. |
| **EnergySource** | The type of energy (coal, oil, gas, hydro, wind, solar, biomass, nuclear). |
| **Consumption** | Records total energy consumption per year, including renewable/fossil shares. |
| **Emissions** | CO₂ emissions data (total Mt and per capita) per year. |
| **ElectricityGeneration** | Electricity generated by each source per year. |
| **PolicyEvent** | Significant policy milestones affecting energy transition. |
| **EconomicIndicator** | GDP, population, and energy intensity per year. |

### Relationships & Cardinalities

| Entity 1 | Cardinality | Entity 2 | Rationale |
|---|---|---|---|
| Country | 1 : N | Year | One country has many years of data |
| Year | 1 : 1 | Consumption | One consumption record per year |
| Year | 1 : 1 | Emissions | One emissions record per year |
| Year | 1 : N | ElectricityGeneration | One year has generation from many sources |
| Year | 1 : 1 | PolicyEvent | At most one policy event per year |
| Year | 1 : 1 | EconomicIndicator | One economic indicator per year |
| EnergySource | 1 : N | ElectricityGeneration | One source contributes to many years of generation |
| EnergySource | 1 : N | Consumption | One source is the primary topic of consumption in many years |

## 2. Logical Model — Normalization to 3NF

The logical model transforms conceptual entities into relations and normalizes them to Third Normal Form (3NF).

### Normalization Steps

**1NF (First Normal Form):**
- All attributes are atomic (no multi-valued attributes).
- Each table has a primary key.
- The CSV data is already in 1NF since each cell contains a single value.

**2NF (Second Normal Form):**
- All non-key attributes depend on the entire primary key, not part of it.
- *electricity_generation*: (gen_id, year_id, source_id, generation_twh) — `generation_twh` depends on the full `(year_id, source_id)` composite, not just year or source alone. So 2NF is satisfied.
- *consumption*: (consumption_id, year_id, source_id, total_consumption_twh, renewable_share_pct, fossil_share_pct) — `renewable_share_pct` and `fossil_share_pct` depend only on `year_id`, not on `source_id`. This violates 2NF but is accepted as a denormalization for this analytical model. In a pure 3NF design, these would be moved to a `year_aggregate` table.

**3NF (Third Normal Form):**
- No transitive dependencies from non-key attributes through other non-key attributes.
- *emissions*: `co2_per_capita_t` can be derived from `co2_mt / population`, but it is kept as a stored column for query performance (a design trade-off). All tables otherwise satisfy 3NF.

### Functional Dependencies

| Table | Functional Dependencies |
|---|---|
| country | country_id → country_name, iso_code |
| year_dim | year_id → year, decade; year → year_id (unique) |
| energy_source | source_id → source_name, source_type, is_renewable |
| consumption | consumption_id → year_id, source_id, total_consumption_twh, renewable_share_pct, fossil_share_pct |
| emissions | emission_id → year_id, co2_mt, co2_per_capita_t |
| electricity_generation | gen_id → year_id, source_id, generation_twh |
| policy_event | event_id → year_id, event_name, event_flag |
| economic_indicator | indicator_id → year_id, gdp_usd, population, energy_intensity |

## 3. Physical Model — DDL Decisions

### Database Platform

Target: **PostgreSQL**

### Table Design & Data Types

| Table | Key Decisions |
|---|---|
| **country** | Uses `SERIAL` auto-increment PK. `VARCHAR(100)` for name with `UNIQUE` constraint. `CHAR(3)` for ISO code. |
| **year_dim** | `INTEGER` year with `UNIQUE` and range CHECK constraint (1800–2100). `VARCHAR(10)` for decade. |
| **energy_source** | `VARCHAR(50)` for name with `UNIQUE`. `source_type` has a CHECK constraint limiting to 'renewable', 'fossil', 'nuclear', 'other'. `BOOLEAN is_renewable` for easy filtering. |
| **consumption** | Composite FK to both `year_dim` and `energy_source`. `NUMERIC(10,3)` for high precision energy values. `NUMERIC(5,2)` for percentage shares with CHECK constraints ensuring 0–100 range. |
| **emissions** | FK to `year_dim`. `NUMERIC(10,3)` for CO₂ Mt, `NUMERIC(8,4)` for per-capita values. CHECK constraints ensure non-negative values. |
| **electricity_generation** | Composite FK to `year_dim` and `energy_source`. `NUMERIC(10,3)` for generation TWh. CHECK ensures non-negative. |
| **policy_event** | FK to `year_dim` with UNIQUE constraint (one event per year maximum). `INTEGER DEFAULT 0` for event flag. CHECK constraint limiting flag to 0 or 1. |
| **economic_indicator** | FK to `year_dim` with UNIQUE. `NUMERIC(16,2)` for large GDP values. `NUMERIC(6,3)` for energy intensity. |

### Indexes

Indexes are created on every foreign key column to optimize JOIN performance:
- `idx_consumption_year`, `idx_consumption_source`
- `idx_emissions_year`
- `idx_gen_year`, `idx_gen_source`
- `idx_policy_year`
- `idx_econ_year`
- `idx_year_dim_year` (for direct year lookups)

### Constraint Strategy

- **NOT NULL** on all FK columns and critical descriptive columns
- **UNIQUE** on country_name, year, source_name, and policy_event/economy year_id
- **CHECK** constraints enforce domain integrity: year ranges, share percentages (0–100), non-negative energy/emissions values, valid source types, and binary event flags
- **CASCADE DELETE** on all foreign keys for clean removal

## 4. Data Population Strategy

### Approach

The DML script (`dml_populate_data.sql`) wraps all inserts within a single `BEGIN / COMMIT` transaction for atomicity.

### Loading Sequence (respecting FK dependencies)

1. **Static dimension tables** (no FK dependencies):
   - `country` — 1 row (Austria)
   - `energy_source` — 8 rows (coal, oil, gas, hydro, wind, solar, biomass, nuclear)
   - `year_dim` — 125 rows (1900–2024)

2. **Fact tables** (depend on dimensions above):
   - `consumption` — 125 rows, one per year with primary source (coal 1900–1964, oil 1965–2024). Uses `JOIN` on year and source name to resolve surrogate keys.
   - `emissions` — 125 rows. Simple lookup join on year.
   - `electricity_generation` — 1,000 rows (125 years × 8 sources). Uses an unpivot pattern via a large `VALUES` block joined to `year_dim` and `energy_source`.
   - `policy_event` — 10 rows (years where `policy_event_flag = 1`). Descriptive event names added manually.
   - `economic_indicator` — 125 rows. GDP, population, and energy intensity from CSV.

### Key Technique: Subquery/CTE Key Mapping

Rather than hardcoding surrogate key IDs, all INSERT statements use this pattern:

```sql
INSERT INTO target_table (fk_column, ...)
SELECT yd.year_id, ...
FROM (VALUES (...)) AS v(year, ...)
JOIN year_dim yd ON yd.year = v.year
JOIN energy_source es ON es.source_name = v.src_name;
```

This approach:
- Makes the SQL self-documenting (uses natural keys in VALUES)
- Eliminates brittle hardcoded IDs
- Ensures referential integrity at insert time

### Electricity Generation Unpivot

Because the CSV stores each source in a separate column (hydro_twh, wind_twh, etc.), the DML converts to row format using a `VALUES` block with 1,000 rows (125 years × 8 sources), each specifying `(year, source_name, generation_twh)`.

## 5. SQL Queries

### Query 1 — [EASY] Total Renewable Generation by Decade

**Purpose:** Show the total renewable electricity generated per decade, revealing Austria's long-term shift toward renewables.

```sql
SELECT
    yd.decade,
    ROUND(SUM(eg.generation_twh)::numeric, 2) AS total_renewable_gen_twh
FROM electricity_generation eg
JOIN year_dim yd ON eg.year_id = yd.year_id
JOIN energy_source es ON eg.source_id = es.source_id
WHERE es.is_renewable = TRUE
GROUP BY yd.decade
ORDER BY yd.decade;
```

**Sample Output:**
```
decade  | total_renewable_gen_twh
--------+-------------------------
1900s   |                  37.00
1910s   |                  49.10
...
2020s   |                 322.49
```

**Explanation:** This query filters `electricity_generation` to only renewable sources (hydro, wind, solar, biomass) using the `es.is_renewable` boolean, then sums generation grouped by decade.

### Query 2 — [EASY] Average CO2 Emissions for High-Renewable Years

**Purpose:** Compute average CO₂ emissions for years where renewable share exceeds 40%, testing the relationship between renewable penetration and carbon reduction.

```sql
SELECT
    ROUND(AVG(e.co2_mt)::numeric, 3)     AS avg_co2_mt,
    ROUND(AVG(e.co2_per_capita_t)::numeric, 4) AS avg_co2_per_capita_t,
    COUNT(*)                              AS num_years
FROM emissions e
JOIN year_dim yd ON e.year_id = yd.year_id
JOIN consumption c ON c.year_id = yd.year_id
WHERE c.renewable_share_pct > 40;
```

**Sample Output:**
```
avg_co2_mt  | avg_co2_per_capita_t | num_years
------------+----------------------+-----------
   58.482   |              6.409   |         2
```

**Explanation:** Joins emissions with consumption to filter by renewable share threshold, then averages CO₂ metrics. Only 2 years (2023, 2024) exceed 40% renewable share.

### Query 3 — [MEDIUM] Multi-Table JOIN: Generation & Emissions After 2000

**Purpose:** Show post-2000 energy mix alongside emissions data, revealing how Austria's generation composition affects carbon output.

```sql
SELECT
    yd.year,
    es.source_name,
    ROUND(eg.generation_twh::numeric, 3) AS generation_twh,
    em.co2_mt,
    em.co2_per_capita_t
FROM electricity_generation eg
JOIN year_dim yd ON eg.year_id = yd.year_id
JOIN energy_source es ON eg.source_id = es.source_id
JOIN emissions em ON em.year_id = yd.year_id
WHERE yd.year >= 2000
ORDER BY yd.year, es.source_name;
```

**Sample Output (first 5 of ~200 rows):**
```
year | source_name | generation_twh | co2_mt  | co2_per_capita_t
------+-------------+----------------+---------+-----------------
2000 | biomass     |          0.000 | 68.745  |           8.579
2000 | coal        |         42.470 | 68.745  |           8.579
2000 | gas         |         78.205 | 68.745  |           8.579
2000 | hydro       |        116.210 | 68.745  |           8.579
2000 | nuclear     |          0.000 | 68.745  |           8.579
```

**Explanation:** Four-table JOIN showing each source's contribution per year. Emissions data repeats per source row (same year) since emissions are year-level, not source-level.

### Query 4 — [MEDIUM] Policy Events per Decade with Avg Renewable Share

**Purpose:** Count policy events per decade and compute the average renewable energy share, showing whether policy activity correlates with higher renewable adoption.

```sql
SELECT
    yd.decade,
    COUNT(pe.event_id)                    AS policy_event_count,
    ROUND(AVG(c.renewable_share_pct)::numeric, 2) AS avg_renewable_share_pct
FROM year_dim yd
LEFT JOIN policy_event pe ON pe.year_id = yd.year_id
JOIN consumption c ON c.year_id = yd.year_id
GROUP BY yd.decade
ORDER BY yd.decade;
```

**Sample Output:**
```
decade | policy_event_count | avg_renewable_share_pct
-------+--------------------+-------------------------
1900s  |                  0 |                   15.83
1910s  |                  1 |                   17.28
...
2020s  |                  2 |                   37.96
```

**Explanation:** Uses LEFT JOIN to include decades with no policy events. Groups by decade to aggregate counts and average renewable share.

### Query 5 — [DIFFICULT] Austria vs. Synthetic EU Benchmark

**Purpose:** Compare Austria's renewable share against a synthetic EU average benchmark using a CTE. This demonstrates advanced SQL techniques: CTEs, computed columns, and CASE expressions.

```sql
WITH eu_benchmark AS (
    SELECT
        yd.year,
        c.renewable_share_pct AS austria_renewable_share,
        ROUND((c.renewable_share_pct * 0.85 + 2.0)::numeric, 2) AS synthetic_eu_avg
    FROM consumption c
    JOIN year_dim yd ON c.year_id = yd.year_id
)
SELECT
    year,
    austria_renewable_share,
    synthetic_eu_avg,
    ROUND((austria_renewable_share - synthetic_eu_avg)::numeric, 2) AS difference,
    CASE
        WHEN austria_renewable_share > synthetic_eu_avg THEN 'ABOVE EU AVG'
        WHEN austria_renewable_share < synthetic_eu_avg THEN 'BELOW EU AVG'
        ELSE 'AT EU AVG'
    END AS comparison
FROM eu_benchmark
WHERE year >= 1990
ORDER BY year;
```

**Sample Output (first 5 rows):**
```
year | austria_renewable_share | synthetic_eu_avg | difference | comparison
------+-------------------------+------------------+------------+--------------
1990 |                   27.76 |            25.60 |       2.17 | ABOVE EU AVG
1991 |                   26.53 |            24.55 |       1.98 | ABOVE EU AVG
1992 |                   29.83 |            27.36 |       2.47 | ABOVE EU AVG
1993 |                   30.72 |            28.11 |       2.61 | ABOVE EU AVG
1994 |                   30.03 |            27.52 |       2.50 | ABOVE EU AVG
```

**Explanation:** The CTE `eu_benchmark` computes a synthetic EU average using the formula `austria_share * 0.85 + 2.0`, modeling the EU as slightly behind Austria's renewable trajectory. The outer query calculates the difference and classifies each year. In production, this would join actual EU-wide data.
